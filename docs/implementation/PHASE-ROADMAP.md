# GRAND LIFE SIMULATION — この先の実装手順

目標：新レイアウトSTEP 16-A～16-Hの設計を、実際に動く人生シミュレーションに段階的に移す。各PHASE終了時には**修正済みZIP、変更履歴、テスト結果、未実装一覧**を出力する。元ZIPと55画面IDを継続保護する。

## PHASE 0（今回完了）— ベースラインと状態分離

原本退避、55ID保持、初期ゲーム状態/ UI状態の分離、テスト基盤、追加ファイル方式による保護。**判定**：原本チェックサム記録・ID互換性テスト合格。

## PHASE 1（今回完了）— PC向け共通レイアウト

ダークテーマ、9カテゴリ・61画面、左ナビゲーション/検索/画面履歴、ヘッダー/右情報欄、共通画面テンプレート。**判定**：61画面の一意登録、画面遷移と主要UI操作のスモークテスト合格。

## PHASE 2 — 61画面の詳細UI・画面間連携

1. STEP 16-A～Hで指定した各画面の項目/ボタン/入力欄を画面仕様ごとにコンポーネント化。
2. マスターデータがない場所は空状態を表示し、実データとデモ表示を厳密に区別。
3. 人物選択、詳細情報リンク、イベントナビゲーション、パンくず、確認ダイアログ、操作フィードバックの仕組みを作る。
4. 項目検証、キーボード操作、スクロール位置、PC画面サイズの検証を追加。

**完了条件**：61画面すべてで対応する表示項目の枠組みと導線があり、未実装操作は明示されている。画面間の参照整合性をテストできる。

## PHASE 3 — ゲームエンジン・時間・基本データ

1. ゲーム世界と人物、時間、乱数シード、イベントキューを独立モジュール化。
2. 日本・2000年開始を基準とし、0～14歳は3か月/ターン、15歳以降は1か月/ターン、早送り無しを実装。
3. 年齢・誕生日・期間更新・死亡時の遷移などをステートマシン化。
4. 進行結果を一括で確定し、ゲーム状態だけを更新する。UIはその読み取り結果で描画。

**完了条件**：同じ初期状態・同じ操作・同じ乱数シードで重要な進行結果を再現でき、境界年齢を含む時間テストが成功。

## PHASE 4 — 人物・家族・学校・学業

1. プレイヤーと背景人物の生成、家族関係、人物履歴を導入。
2. 乳幼児期から進学まで、学年・進路・学力・学習行動・受験/合否を実装。
3. EDU6画面とPERSON7画面へ実データを接続。
4. 人物生成量を制限し、長期間プレイでも保持する情報を整理。

**完了条件**：人物・家族・学業のイベントが時間経過で変化し、同一の学業データがダッシュボード/詳細/履歴に一貫して表示される。

## PHASE 5 — 職業・企業・生活・資産

1. 適性に応じた就職・転職、副業・経営・企業データを導入。
2. 収入/支出・金融資産・借入・保険/年金・家計記録を整合的に計算。
3. LIFE-02～08とWORK-01～05の個別操作、履歴、計算を接続。
4. 収支や資産が複数画面で食い違わないよう、会計計算の単一責任化と回帰テストを行う。

**完了条件**：各ターンの現金収支・資産変動を説明でき、家計・仕事の履歴が再計算と整合する。

## PHASE 6 — 健康・社会・ニュース・人生イベント

1. 健康/医療/生活習慣/精神/病気・けがの変化を実装。
2. 日本・世界の経済・時代・地域情報をゲーム変数に接続。
3. 人生イベントの発生条件・選択肢・結果・履歴・評価を実装。
4. 重要イベントの右パネルを実データ連動に変更し、選択待ち状態の優先処理を追加。

**完了条件**：ターン更新で健康・社会・イベントが統一ルールに従って動き、選択結果がゲーム状態へ確定する。

## PHASE 7 — 記録・死亡・相続・セーブ・ロード

1. 時間軸の履歴、過去の人生、死亡処理・簡易相続・人生評価を導入。
2. ローカルIndexedDBとJSONエクスポート/インポート、世代別スロット、自動保存を実装。
3. スキーマバージョン、移行処理、破損時の標準復旧を追加。
4. ゲーム状態のみを正として保存し、UI状態の保存方針は別に管理する。

**完了条件**：保存/ロード前後でゲームの重要状態が一致し、破損・旧版データへのテストが成功。

## PHASE 8 — 全画面・長期プレイの統合試験と完成判定

1. 61画面と主要操作のE2E、年齢境界、複数人生、家計・人物・イベントの回帰テスト。
2. 1920×1080/1440×900/1200×800で視認性、操作性、スクロールを再検証。
3. 長期プレイのデータ肥大化、保存安定性、再現性、例外・性能を検証。
4. バグ修正、仕様との照合、未完成機能がないかの最終監査、成果物ZIPと検証レポートを作成。

**完了条件**：必須シナリオが一通り実行でき、重大バグ・未接続の必須操作がなく、設計との差分が記録されている。

## 毎PHASEで守る原則

- 既存55IDの変更・削除禁止（必要なら移行表と互換レイヤーを別途設計）。
- ゲーム状態とUI状態を分けて保持し、ゲームロジックをDOMへ直結しない。
- 最初にテストを追加し、実装後に再実行。実データ未接続は未実装と明記。
- 前PHASEのZIPを保存し、差分比較・ロールバック可能な状態を維持。
- 実装内容、未実装、検証結果、既知の制約を毎回レポート化する。
