# 第20段階 実装・検証報告

## 基準と互換性
第19段階（2.0.0）のZIPを基準に第20段階（2.1.0）を実装しました。従来の55画面IDに学業6画面を加えた61画面、9カテゴリを維持し、表示と新しい操作は日本語にしています。原本・過去の実装報告は保持しています。

## 実装済み
- 融資契約の個別台帳：契約番号・元本残高・借入額・借入年月・返済期限・延滞月数・月利率を契約別に管理。既存の `loanBalance` は契約元本の合計として維持します。
- 複数融資の返済：手動・自動返済とも返済期限の早い契約から順に元本へ充当します。残高、資金、契約残高の整合性を維持します。
- 返済実績：返済年月・対象契約・金額・手動／自動の区分を直近120件まで保存。事業画面に契約一覧と実績を追加しました。
- 延滞管理：契約ごとに未返済の期限到来を判定し、信用点数は同一月に最大3点減少。既存の合計延滞指標も維持します。
- 設備個別売却：設備番号を選んで売却し、対象設備の帳簿価額・事業資金・台帳を整合させます。従来の全設備一括売却も維持します。
- 保存互換性：旧データの合計融資残高は読み込み時に単一の互換契約へ補完します。契約合計と集計残高が不一致の保存データは拒否します。

## 制限と未検証
- 借入契約別の元本は個別管理になりましたが、契約単位の返済額指定・各契約ごとの分割返済スケジュール（毎月の予定額一覧）は未実装です。既存の自動返済額は事業全体への共通設定です。
- 借入と延滞はゲーム用の簡易モデルであり、現実の金融制度を再現しません。
- 設備の売却率は現行の帳簿価額70%です。設備種別に応じた中古市場価格や耐用年数変更のUIは未実装です。
- 実HTTPサーバー経由のChrome起動、全61画面の実描画、ブラウザを終了・再起動した後の保存維持は未検証です。
