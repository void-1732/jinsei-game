# 第36段階 実装・検証報告

## 対象

第35段階（バージョン3.6.0）をベースに、人生終了時の住宅・資産・事業・負債・老後制度と相続評価の接続を改善しました。バージョン3.7.0。

## 実装内容

- `js/core/estateSystems.js` を追加し、個人の現金、投資、住宅評価額、事業運転資金、事業設備を資産として集計。
- 個人借入金、住宅ローン元本、事業未払金、事業融資を負債として差し引き、差引純資産を表示。
- 廃業済み事業の清算済み財産を重複計上しない。年金の月次見込みは表示用参考値であり、相続財産には算入しない。
- 債務超過でも純資産のマイナスを明細に残し、分配可能額は0円で下限処理。
- 従来どおり仮の相続税10%と均等分配を採用（現実の制度とは異なる）。配偶者・子を優先し、該当者がいない場合は父母。
- 資産画面の純資産と人生終了時の相続財産で共通の財産内訳計算を使用。
- 人生年表・記録画面に死亡時の財産内訳・債務・年金の扱いを表示。
- 新形式の相続内訳を保存検証でチェック。既存の `breakdown` のない第35段階以前の人生記録も読み込み可能。
- 61画面、9カテゴリ、既存の保存スキーマv7は維持。

## 未実装・注意

- 実際の相続税・遺産分割・遺言・法定相続分、相続放棄や家・事業の現物分割は未実装。
- 住宅ローンの未払利息・延滞の履歴は引き続き既存の会計管理に依存し、個人負債と重複しないよう財産評価で追加計上しない。厳密な債務明細統合は今後の課題。
- 過去の人生記録は再計算せず、旧形式の分配値をそのまま保持。
- 年金は受給済みで現金として残っている部分のみ現金に含まれ、将来の受給見込みは相続評価に含めない。
- 実HTTPサーバー経由のChrome描画、永続保存のブラウザ再起動テストは未実施。

- `npm test`：190件成功（第35段階までの185件＋新規5件）
- `node --check`：全JavaScriptファイル成功
- 61画面の既存構成：画面カタログの規定を維持
- ZIPの整合性：正常
- データの不整合拒否、債務超過、複数相続人の均等分配、旧相続データ互換性：自動テストで確認
